# Deep Learning Room · 深度学习资料与 HTML 学习室

把一个学习主题整理成全面、详细、易懂且来源可靠的中文资料，讲清原理和真实项目如何应用，并提供简洁的HTML阅读文档。

这是给AI Agent使用的Skill，不是独立运行的软件。Markdown是内容主源，HTML用于集中阅读；支持Obsidian Canvas、Mermaid与SVG。默认不生成自测、学习记录、掌握度评分或打卡功能。

## 快速开始

安装后输入：

```text
请使用 $deep-learning-room。
我想学习【学习主题】。
我的基础是【已有基础，不填则按入门处理】。
我重点关注【关注方向，不填则先梳理主题，再确定核心范围】。

请整理全面、详细、易懂、来源可靠的中文学习资料。
围绕“是什么、解决什么问题、原理是什么、如何运用”展开，
重点读懂真实 GitHub 项目，讲清使用场景、接入位置、调用链和运行方法。
提供 Markdown、必要图解、面试题与详细解答，以及简洁的 HTML 阅读文档。
```

例如学习RAG，可以补充：“我会Python，关注企业文档问答，请重点解释检索质量、语义重排和回答可追溯性。”只提供主题也可以；范围过大时先明确核心与扩展部分。

## 本轮讨论确定的方向

这次调整来自实际资料生成与阅读反馈：仅有流程、图表和学习管理组件，不能弥补原理解释与真实应用不足。删除自测和记录界面也只是第一步，需要重新研究并补充正文。

现在的优先级是：

1. **文档全面、详细、易懂**：核心机制用具体输入、中间过程和输出讲清，解释设计理由、前提、误解和取舍。
2. **搜索全面且可靠**：围绕主题范围覆盖基础、当前行为、应用与局限，优先论文、官方文档和源码，记录版本及实际读取范围。
3. **内容围绕四个问题**：是什么、解决什么问题、原理是什么、如何运用；不要求每节机械重复四个标题。
4. **真实项目讲到如何应用**：读取实际代码，解释技术在系统哪一层、上下游如何连接、如何运行与定位失败。
5. **阅读体验服务正文**：面试解答直接展开，保留有价值的图解和参数演示；默认移除自测、记录、自评、打卡和进度管理。

用户明确要求练习或辅导时可以增加相应流程，默认生成过程不等待逐题作答。后续维护是补充知识、案例与来源，不是建立个人学习档案。

## 六步如何工作

| 步骤 | 主要产物与要求 |
| --- | --- |
| 搜集并核实资料 | 核实主题与版本；检查Agent Reach或其他可用渠道；读取一手内容，建立就近引用和来源索引。 |
| 确定重点与路线 | 梳理前置知识、模块关系与推荐顺序；学习地图关联实际章节，图形按理解需要选择。 |
| 编写完整文档 | 解释机制、设计理由、具体算例或执行过程；不把目录、摘要或外链当成正文。 |
| 讲透真实应用 | 从代表性项目追踪入口、关键函数、数据与分支；提供配置、命令、验证和排错。 |
| 整理面试解答 | 集中给出问题、详细解释、口述版与追问；不按章节凑题，不冒称企业真题。 |
| 根据反馈完善 | 把疑问与新证据补回正文，同步图解及HTML，保留用户原有笔记。 |

## 真实项目必须讲到什么程度

不只是贴仓库链接或转述README。一个主案例应能回答：

- 项目解决什么具体问题，为什么在这里使用这项技术？
- 完整系统里，它负责哪个环节，哪些工作由其他模块完成？
- 输入怎样进入关键函数，返回结果如何被后续代码消费？
- 环境和配置是什么，哪些命令能复现最小路径？
- 哪些结果实际运行过，哪些只是作者报告或预期？
- 失败应定位到哪一步，换到自己的场景需改什么？

固定tag或commit并链接关键源码。官方SDK、示例、社区应用、研究原型和生产部署分开说明；SDK或自编demo不能替代真实应用分析。找不到可核实项目时，说明检索缺口并分析最接近的公开实现，不编造采用者或效果。

离线测试、mock和真实API调用也分开记录。测试通过不能证明模型准确率或生产收益；作者报告的性能指标未复现时明确标注。未公开内部实现不靠猜测补齐。

## 默认交付

```text
学习主题/
├── README.md                 # 统一阅读入口
├── plan.md                   # 范围、前置知识与阅读路线
├── sources/                  # 来源索引、原文归档与中文解读
├── notes/                    # Markdown完整正文
├── diagrams/                 # Mermaid等源码及SVG
├── learning-map.canvas       # 关联章节的Obsidian地图
├── practice/                 # 案例代码与实际运行输出
├── interview.md              # 面试题与直接展开的解答
├── index.html                # 简洁的HTML阅读文档
├── scripts/                  # 实际使用的构建脚本
└── verification.md           # 检查结果和未验证部分
```

结构按主题、格式要求和已有目录调整，不创建空文件凑交付。HTML包含完整正文，优先目录、行宽、行距、代码/表格阅读和图解放大，不做营销首页或统计卡片墙。参数变化确实有教学价值时才加交互，静态内容尽量离线可读。

默认没有题目与答案分离、隐藏提示、学习记录、进度条或导入导出；面试答案直接可读。需要服务、账号、密钥、付费或特殊环境时说明条件。不能运行的部分标为未验证。

## 安装

### 手动安装

在GitHub选择 **Code → Download ZIP**，解压后将目录命名为 `deep-learning-room`，放入宿主Agent的技能目录。保留整个目录，确保 `SKILL.md` 位于根部，`agents/` 和 `references/` 随包安装。

Codex默认路径：

```text
~/.codex/skills/deep-learning-room/SKILL.md
```

设置 `CODEX_HOME` 时使用其下的 `skills/deep-learning-room/`。其他支持SKILL.md的工具按自身约定安装；`agents/openai.yaml` 是Codex的界面元数据。

### 使用Git安装（macOS / Linux）

```bash
git clone https://github.com/GitHubZkLn/deep-learning-room.git "${CODEX_HOME:-$HOME/.codex}/skills/deep-learning-room"
```

目标已存在时先保留本地修改，再合并更新，不直接覆盖。安装或更新后可在新会话调用 `$deep-learning-room`。

## 更新已有学习资料

```text
使用 $deep-learning-room 重整我已有的学习资料。
先检查原理和应用缺口，补充关键机制与真实GitHub调用链，
不要只删除自测和学习记录或调整页面样式。
保留原有笔记，同步Markdown、HTML、图解和来源，说明实际验证范围。
```

普通概念答疑或单篇摘要不自动生成整套学习库。非技术主题可以使用同一内容主线，以原始证据、案例和分析过程替代GitHub代码，不强套技术模板。

## 工具与验证范围

宿主Agent需要相应联网、文件和执行能力。研究前检查 [Agent Reach](https://github.com/Panniantong/agent-reach)，环境与授权允许时按当前官方说明安装；受限时使用其他可用渠道继续，不要求配置所有平台。本仓库不捆绑这些工具，也不默认调用付费服务或公开部署网页。

本版规范根据一次Jev学习资料的实际重整反馈修订，重点纠正内容偏浅、应用脱节和学习管理组件过多。该案例的结果不是所有主题都必须复制的章节、项目或测试数量。技能格式与内部引用可静态验证，但不能据此保证每次生成的内容质量；不同主题与宿主能力仍需逐次检查。
