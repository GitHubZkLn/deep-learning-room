# Deep Learning Room · 深度学习资料与 HTML 学习室

**输入一个学习主题，让 AI 整理出有来源、有原理、有真实应用、有练习的学习资料，再通过 HTML 引导你自主学习。**

学新东西时，最容易卡在这一步：解释看懂了，demo 也跑通了，但遇到实际问题，仍然不知道什么时候该用、怎么接入、出了错怎么查。

Deep Learning Room 把资料搜集、知识组织、深入讲解、实际应用、练习和复盘整理成一个可复用的 Skill。它主要用于生成和维护学习资料，不要求你在聊天中逐题回答才能继续制作。

> 本仓库是一套给 AI Agent 使用的技能说明与配套规范，不是独立运行的软件，也不是已经生成好的某个主题课程。

## 快速开始

安装后，在支持技能调用的 Agent 中输入：

```text
请使用 $deep-learning-room。
我想学习：RAG。
我的基础：会 Python，了解基本的大模型调用。
关注方向：企业文档问答，尤其是检索质量和回答可追溯性。
学习目标：能独立搭建最小系统、分析失败原因，并判断何时不值得用 RAG。
请生成完整学习资料与 HTML 学习室。
```

也可以只提供主题，默认按入门处理。填写基础、方向和目标，能让资料更贴近你实际要解决的问题。主题过大时先划分核心范围和扩展方向。

## 六个模块，分别解决什么问题

| 模块 | 想解决的问题 | Skill 如何约束 |
| --- | --- | --- |
| ① 可信资料 | 内容从哪里来，能不能相信？ | 检查 Agent Reach 和可用渠道，检索国内外论文、官方文档、规范、项目与可靠解读；记录来源、日期、版本、读取范围，并区分原文结论与教学解释。 |
| ② 学习地图 | 先学什么，概念之间有什么关系？ | 梳理前置依赖、推荐顺序、必学/重点/选学及能力目标；用 Canvas 关联章节，使用可编辑图解展示流程与机制。 |
| ③ 深入原理 | 除了记结论，能不能说清为什么？ | 按直觉、机制、原理、应用、取舍和迁移逐层展开；解释公式推导、执行过程、边界、反例及常见误解。 |
| ④ 真实应用 | 遇到什么问题时该想到它，怎样用进项目？ | 追溯真实案例中的原有问题、接入环节、输入输出、使用方式、效果证据、成本和局限，再分析适合尝试及不值得采用的场景。 |
| ⑤ 分层实践与自测 | 到底是看懂了，还是能独立做？ | 从最小案例推进到改条件、独立任务、排错与迁移；每章安排自测，提示和答案默认隐藏，要求如实记录实际运行情况。 |
| ⑥ 复盘维护 | 下一次怎么继续，误区怎么补回来？ | 分开记录阅读、自评与练习证据；将新发现补回笔记，同步页面与图解，保留用户记录和下一次起点。 |

## “深入”具体指什么

不是把正文写得更长，而是让核心知识点回答这些问题：

- 它解决什么问题，为什么原来的方法不够？
- 一个具体输入如何经过中间步骤变成输出？
- 为什么这样设计，依赖哪些假设和前置条件？
- 什么情况下会失效，有哪些反例和容易混淆的概念？
- 和其他方案相比，收益、代价与适用范围是什么？
- 放到真实任务中该从哪里接入，第一步怎样验证？
- 条件变化或运行失败后，怎样定位、调整和迁移？

公式不能只列结果，代码不能只讲语法，图解不能只是大纲换个形状。核心解释应留在资料里，外链用于继续深入。

对于非技术主题，使用证据比较、案例分析、决策或写作任务，不强行套用代码和 GitHub 项目。

## 会生成哪些内容

以下是默认学习库结构示意，具体内容按主题和用户要求生成：

```text
学习主题/
├── README.md                 # 统一阅读入口
├── plan.md                   # 范围、路线、目标和预计用时
├── sources/                  # 来源索引、原始资料和中文解读
├── notes/                    # Markdown 分章正文
├── diagrams/                 # 可编辑图解源码与 SVG
├── learning-map.canvas       # Obsidian 学习地图
├── practice/                 # 案例、任务、必要代码和运行记录
├── questions/                # 自测题与提示
├── answers/                  # 独立参考答案与实现
├── progress.md               # 进度、误区、复习和下次起点
├── room/                     # HTML 学习室与本地资源
├── scripts/                  # 本次资料实际使用的构建脚本
└── verification.md           # 已检查、未验证及阻塞事项
```

Markdown 是正文主源，HTML 尽量由它生成，避免维护两套内容。核心 SVG 直接嵌入笔记，Canvas 关联实际章节，图解保留源码和再生成方法。

HTML 不只是目录页：它应包含完整正文、章节导航、案例、练习、可展开的提示与答案、复盘和进度记录。参数变化确有帮助时再加入交互演示，同时保留静态解释。静态内容尽量离线可读，需要本地服务时附启动方式。

以上是技能要求的交付目标，实际产物受主题范围和宿主 Agent 能力影响；未完成或未验证的部分必须如实说明。

## 安装

### 手动安装

1. 在仓库页面选择 **Code → Download ZIP**，解压下载文件。
2. 将解压后的目录重命名为 `deep-learning-room`。
3. 将整个目录放入技能目录，保证 `SKILL.md` 直接位于 `deep-learning-room/` 下，保留 `agents/` 和 `references/`。

Codex 默认路径：

```text
~/.codex/skills/deep-learning-room/SKILL.md
```

设置了 `CODEX_HOME` 时使用其下的 `skills/deep-learning-room/`。其他支持 SKILL.md 的工具按各自目录约定安装；本仓库中的 `agents/openai.yaml` 是 Codex 界面元数据。

### 使用 Git 安装到 Codex（macOS / Linux）

```bash
git clone https://github.com/GitHubZkLn/deep-learning-room.git "${CODEX_HOME:-$HOME/.codex}/skills/deep-learning-room"
```

若目标目录已存在，先保留本地修改，再合并更新，不要直接覆盖。安装后新建会话，尝试调用 `$deep-learning-room`。

## 更多用法

### 指定应用方向

```text
使用 $deep-learning-room 学习消息队列。
我会 Java 和 Spring Boot，重点是订单系统中的异步处理。
请讲清什么时候值得引入、如何处理重复消息，以及失败后怎样排查。
生成 Markdown 学习库、图解、实践和 HTML 学习室。
```

### 延续已有学习资料

```text
使用 $deep-learning-room 更新我已有的学习目录。
根据这次练习结果补充没理解的机制、真实应用和排错过程。
同步 HTML 与相关图解，保留原有笔记、回答和进度。
```

### 使用非技术主题

```text
使用 $deep-learning-room 学习论证分析。
我按入门开始，重点是识别前提、证据与结论之间的关系。
请用可追溯案例、分析练习和评价标准组织 HTML 自学资料。
```

## 工具与能力要求

- 宿主 Agent 需要具备相应的联网研究、文件生成和执行能力，才能完成完整流程。
- 研究阶段会检查 [Agent Reach](https://github.com/Panniantong/agent-reach)。环境和授权允许时，按当前官方说明安装所需能力；无法安装或渠道受限时，使用其他可用搜索渠道继续。
- 本仓库不捆绑 Agent Reach，也不要求把所有平台都配置好。
- 公式、图解渲染和示例运行所需依赖按实际主题选择，必要脚本和启动说明随生成的资料交付。
- 默认不需要接入独立 AI 服务才能阅读生成的静态资料；如果没有真实评估能力，页面应提供参考答案和自查标准，不伪装成 AI 自动批改。

## 使用边界

深入学习是内容与任务的设计目标，不承诺“看完就成为专家”。阅读完成、自评掌握和实际练习证据需要分开记录。

真实案例与教学示例必须区分；没有运行的代码不得标为验证成功。持续维护发生在后续交互中，未设置自动任务时不承诺后台更新。

**当前验证范围：** 技能格式、内部文件引用及打包完整性已检查；尚未完整试跑一套课程生成流程。不同 Agent 的执行质量和可用工具会影响最终产物。
