# 阅读文档、维护与交付验收

## 文件结构与主源

尊重用户和已有目录约定。下列结构用于说明职责，按实际交付调整，不创建无用途的空目录：

```text
topic/
  README.md                 统一入口与运行说明
  plan.md                   范围、前置知识与简短阅读路线
  sources/                  来源索引、许可范围内的原文与中文解读
  notes/                    Markdown 分章正文
  diagrams/                 图解源码与 SVG
  learning-map.canvas       关联真实章节的学习地图
  practice/                 案例代码、必要上游文件与实际运行输出
  interview.md              面试题及直接展开的详细解答
  index.html                完整阅读文档
  scripts/                  实际使用的构建与图解生成脚本
  verification.md           已检查、未验证及必要运行条件
```

Markdown为正文主源，HTML尽量由其生成，避免人工维护两套长正文。主源变化后重建相关产物并检查一致性。保留图解源码、生成脚本或明确生成步骤，不只交截图；记录必要工具和版本。

Canvas为有效JSON，节点引用实际章节，ID稳定，边有明确含义，路径相对学习库根目录。放进已有Obsidian库的子目录时，处理库根目录不同造成的引用差异。

Markdown与HTML使用相对链接及本地资源，正确转换内部锚点、Obsidian链接与嵌入，不能把 `![[...]]` 留成普通文字。核心SVG直接显示在正文，图注说明来源和教学简化。

## HTML以连续阅读为主

首页简短说明主题、范围、前置知识和推荐阅读入口，随后进入正文。需要时提供“先看真实应用”的入口。不做营销式首页，不堆大卡片、统计数字、口号、过大留白或无用动画。

正文完整呈现原理、具体例子、案例、代码解释和面试答案。使用清楚的标题层级、合理行宽与行距、章节导航和相关知识跳转。代码、公式、表格在手机上可读；长代码或宽表可局部滚动，避免整页横向溢出。图解可放大，基础导航支持键盘。

核心解释、参考实现和面试解答默认直接展示，不藏进分层提示或“先答后看”的流程。确实很长的日志或补充材料可以折叠，但不能遮住理解主线所需内容。

默认不生成自测、答题输入、掌握度自评、学习记录、进度条、打卡、复习表单和记录导入导出。搜索框、字号调整、图解放大及参数演示是阅读工具，不应因移除学习管理而一并删掉有用功能。

## 图解与参数演示

学习地图表达概念关系，流程图表达顺序、数据流或判断分支，按内容选择图形，不给每章强配所有形式。图中用简体中文，解释箭头含义，自行整理标“学习示意图”，注明重要简化和来源。

参数变化或动态过程确实有助理解时再做交互演示。说明输入、指标、公式、变化原因、假设和边界，并配静态解释。合成数据、本地公式计算、真实模型调用要区分；不让浏览器随机数或固定响应冒充真实AI服务。

静态正文与图解尽量离线可读，避免强制在线字体、图标或图解渲染。诚实区分“双击可读”和“需本地服务”；后者提供依赖、工作目录、启动命令和准确入口。不默认公开部署或接入外部账号。

## 更新已有资料

先评估内容缺口：原理是否只列名词，应用是否只有SDK或自编demo，案例是否读到关键代码，结论是否可追溯。内容重整要补充这些缺口，不能仅删除自测、改导航或重做样式。

优先保留用户原有笔记与文件。移除学习记录功能时，不自动清空旧浏览器存储或删除个人回答；不再把记录入口呈现在阅读页面。根据新证据更新正文、来源与图解，再重建HTML；记录实质修正原因与版本。未设置自动任务时不声称会后台维护。

## 验收

先验内容，再验产物。检查要实际执行，不能把计划写成结果；工具不可用时明确未验证及影响。

**内容与证据**

- 约定范围有完整正文，无空章节或占位摘要；能读懂“为什么”和“怎么用”，而不只是看到概念列表。
- 核心机制有输入、中间过程、输出与解释；公式或代码没有跳过关键推理，边界、误解和替代方案有说明。
- 真实主案例追到关键源码，讲清接入位置、上下游、调用链、运行步骤和失败定位；SDK、官方示例、自编demo与应用项目不混淆。
- 关键结论可查来源；作者报告、离线测试、模拟与真实在线运行分开，未复现的指标没有写成自己实测。
- 面试解答直接可读且解释原因；没有默认自测、个人记录或填表要求。

**文件与页面**

- 检查Markdown/HTML本地链接、锚点、图片和资源；本地有效与外部未验证分开报告。
- 解析Canvas JSON，检查节点、边与文件引用；未打开Obsidian时只声明静态检查。
- 检查SVG有效且文字、连线、图注清楚；源码与生成结果一致。
- 运行构建，核对全部正文、图解和答案已同步进入HTML，不覆盖用户笔记。
- 用可用浏览器检查首页、代表性原理与案例章节、导航、代码/表格、图解放大、桌面和手机阅读；静态检查不能代替目视检查。
- 实际操作存在的搜索或参数演示，检查静态离线阅读；不为验收创建无关功能。

**案例与交付**

- 在可用环境和授权内运行最小路径及与案例有关的上游检查，保存必要命令与结果。不能执行的在线部分提供步骤并标未验证。
- 交付命令对应实际文件和依赖，包内若只有源码子集，清楚说明可运行范围及完整仓库入口。
- README链接正文、地图、真实案例、实践、面试解答、来源与HTML。交付简述覆盖范围、入口、实际验证和未验证部分，推荐一个能直接看出应用价值的起点。
