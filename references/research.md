# 资料来源与研究

## 工具与覆盖范围

核实主题同名歧义、范围和版本。用中英文名称、关键术语及应用场景检索，兼顾基础知识、当前接口、真实应用、限制和争议。非技术主题使用对应领域的研究、原始记录、规范或原著。

检查本地Agent Reach（命令发现或 `agent-reach --version`），项目地址：https://github.com/Panniantong/agent-reach 。环境有该skill时读取适用指导，不假设每台机器都已安装。

未安装时，在环境允许且现有授权涵盖安装工具的范围内，读取当前官方安装说明再安装，不固定过时命令。仅配置任务需要的渠道。安装失败、登录限制或访问受限时简要说明，改用现有搜索、浏览器、连接器、官方文档或公开API继续。以实际取得的内容确认可用；未访问的平台不能列成已完成搜索。

先取得足以建立地图的资料，再针对章节的证据缺口补充检索。覆盖是否充分，看核心问题是否有可靠依据，不看链接数量或是否遍历所有平台。

## 选源与可信度

- 优先源头论文、官方文档、规范和原始项目；可靠外部解读用于补充解释、实践问题和不同观点。
- 博客、小红书、抖音等可提供线索，关键技术结论回到一手资料核对；不以热度、Star数或作者身份替代证据。
- 官方文档用于核对产品声明和公开行为；效果比较、生产采用和普适结论仍要查对应条件与证据。
- 读取实际支持结论的段落。搜索片段、论文摘要不等于全文；README不等于源码审计；项目存在不等于生产落地。
- 保留基础资料和近期变化，按版本解释差异。来源冲突时比较定义、条件、版本及证据，无法判断则保留分歧并说明影响。
- 未公开内部实现保持未知。通用算法、自己的推导或教学简化必须说明性质。

## GitHub 项目研究

从相关应用项目而非仅SDK开始寻找实际接入位置。读取仓库说明、入口、相关模块、示例、必要测试或评测报告；调用链讲解标准见 [content.md](content.md)。使用tag或commit链接，避免分支更新后正文与源码不符。

下载或克隆失败时，可通过可用的官方API或连接器获取相关文件。记录实际读取的文件范围；仅取到文件子集时不宣称完整仓库审计或完整可运行。包内包含上游代码时检查许可证、保留原作者声明；按需要记录文件清单与哈希，区分原始文件和教学修改。

## 来源索引与中文整理

为来源分配稳定ID，记录标题、作者/机构、链接、发布或更新日期、访问日期、版本、实际读取范围、关联章节和支持的结论。代码记录tag/commit；未注明日期不猜测。后续仅重新核对部分来源时逐项更新，不把旧资料统一改成最新日期。

按必读、选读、查阅组织，并说明用途。重要结论及项目效果在正文附近引用，来源索引供统一检索，不代替就近引用。

按可访问和许可范围归档原文；不能保存全文时留元信息、链接和必要摘要，不将来源卡标成全文镜像。外文忠实整理成中文，保留关键术语，明确是摘要、解读、节译还是全文翻译，不默认翻译全部原文。

区分官方说明、独立研究、作者观点、本次运行观察、综合解释及教学示例。用自然表述或必要标签消除歧义，不逐句堆标签。
